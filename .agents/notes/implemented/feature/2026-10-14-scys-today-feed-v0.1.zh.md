# Agent Note: SCYS Today Feed V0.1

Status: implemented

[English](2026-10-14-scys-today-feed-v0.1.md) | 中文

## Problem

生财有术的“今日生财”原先固定搜索关键词，无法呈现已验证的近期、热门筛选和精华筛选查询结果作为主动信息流。

## Decision

今日生财通过现有、经过认证的 Desktop 私有桥读取三种固定信息流操作。Host 在内存中为每种成功查询缓存十五分钟，同一模式的并发请求合并为一次，只接受布尔刷新标记；刷新失败时返回上次成功结果及安全状态码。UI 按顺序读取三种模式，先以精华结果、再以热门结果组成最多八篇精选，随后展示剔除精选身份后的最多十二篇近期文章。筛选与排序使用来源 `entityType`、`entityId` 和由 `gmtCreate` 映射的发布时间；相同发布时间时以真实互动数据排序。UI 只说明采用了服务端筛选，不会在缺少逐篇证据时添加官方热门或精华徽标。精选卡沿用 AI 破局俱乐部的文字优先布局，显示去重后的纯文本摘要、紧凑元数据和独立原文入口；SCYS 图片数据缺失时不显示占位。搜索、项目、详情和评论日期统一显示上海时间，已知内部内容类型转换为中文。评论仍由用户主动加载，并区分读取中与读取完成状态。已保存授权的重连只对已分类网络错误以及 HTTP 408、425、429 或 5xx 重试，Host 内存间隔为两分钟、四分钟、八分钟、最长十五分钟。授权记录缺失或无效时不重试；重试不会启动 OAuth，并发状态请求共享一次尝试，连接成功后清除退避状态。

## Alternatives considered

- **继续把固定 AI 搜索作为首页默认内容** — 这会在无关键词近期查询已验证后，继续把关键词样本误表示为今日入口。
- **新增 Remote 或 HTTP 信息流端点** — 现有经过认证的私有桥已承载这些固定只读操作；增加第二条通道会扩大访问面，却没有增加能力。
- **在 Host 外持久化信息流快照** — 进程内缓存已满足十五分钟复用需求，不必让来源内容持久化或增加第二个所有者。
- **把每条结果标记为官方热门或精华** — 来源有时不返回逐篇标记，因此查询筛选条件不能证明单篇属性。

## Consequences

用户打开“今日生财”时无需先搜索，精选和最新区域最多展示二十条不同的真实来源记录。刷新失败时可以继续显示此前读取的内容，同时标明缓存状态和安全错误码。当前规范化信息流没有图片字段，因此本版本不显示图片占位，也不推断图片；图片能力需先由来源字段支持。Desktop 数据验收和视觉验收仍与构建、单元测试结果分开报告。
