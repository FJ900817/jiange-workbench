# Agent Note: Studios 媒体创作使用独立编辑区与历史滚动

Status: implemented

[English](2026-10-18-studios-media-creation-independent-scroll.md) | 中文

## 问题

媒体创作路由占用高度有限的 Studios 工作区，但内容根节点和网格会随内容自然扩展。历史列表虽然声明了溢出滚动，父容器却没有受限高度，因此长会话会拉长页面，而不是与模型设置及提示词编辑区独立滚动。

## 决策

Image Studio 与 Video Studio 将模型设置和提示词编辑器放在左列，将连续历史放在右列。路由根节点填满可用工作区高度；两列网格在标题下方使用剩余高度，参数区和历史列表分别在各自列内滚动。历史列表限制滚动链传递，因此鼠标滚轮或触控板在其边缘继续滚动时不会带动工作区页面。

视口宽度不超过 720 CSS 像素时，编辑区和历史区改为纵向排列。路由整体可以滚动，同时历史区仍保持受限高度和独立滚动区域。会话、作品选择、参考对象及版本状态仍由同一个 React 组件和 Host Remote 管理。

## 考虑过的替代方案

**继续只滚动整个页面。** 被拒绝，因为长历史会把设置和提示词移出视口，用户无法在编辑时独立浏览历史。

**为历史区指定固定像素高度。** 被拒绝，因为 Shell 和视口会改变可用工作区高度；网格可以直接使用路由剩余高度，不必固定桌面尺寸。

## 验证

定向 Client 测试、Client 类型检查和 Client bundle 构建覆盖变更后的路由。隔离的真实 Harness Host 与正式 Client 浏览器运行验证两种模式、历史独立滚动、作品选择及参考展示、版本关联，以及 Provider 请求数为零。正式 Desktop 部署仍需另行获得批准。

## 后果

桌面布局中，历史独立滚动时两列都保持可见；如果参数区控件超过可用高度，参数列也会独立滚动。窄屏下页面纵向滚动，受限高度的历史区仍可独立滚动。Host API、持久化数据、媒体任务行为和正式 Desktop 资源均未改变。
