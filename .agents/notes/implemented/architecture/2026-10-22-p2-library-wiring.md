# Agent Note: P2 wires talkcraft/shotcraft select-prompts + all three library lints into the plan validation chain

Status: implemented

## Problem

After P0/P1, the wiring was half-done: `TALKCRAFT_SELECT_PROMPT` and
`SHOTCRAFT_SELECT_PROMPT` existed as files (both header-noted "injected by
video-packaging-model.ts") but were never injected, and the three plan-level
lint validators (`validateAikouLibraryRefs`, `validateTalkcraftLibraryRefs`,
`validateShotcraftLibraryRefs`) were only called from specs — the production
`validatePackagingPlan` chain accepted any non-empty `componentId` for an
allowlisted lib, so an illegal component reference could reach the timeline.

## Decision

1. **Prompt injection (Host):** `VIDEO_PACKAGING_SUGGESTION_SYSTEM_PROMPT` in
   `video-packaging-model.ts` now concatenates all three guides after the base
   instruction, in AIKOU's existing `'\n\n' + PROMPT` style:
   `AIKOU_SELECT_PROMPT` → `TALKCRAFT_SELECT_PROMPT` → `SHOTCRAFT_SELECT_PROMPT`.
   shotcraft uses the generated prompt (`shotcraft-select.js`, regenerated from
   `shotcraft-index.json`, never hand-edited) rather than Host-side retrieval —
   all three libraries share the prompt-injection architecture.

2. **Lint chain (client):** `validatePackagingPlan` in `packaging-plan.js`
   imports the three validators and, after the structural per-proposal loop,
   runs each on a lib-filtered sub-plan
   (`{ proposals: plan.proposals.filter(p => p.libraryRef?.lib === '<lib>') }`).
   Each validator skips proposals without `libraryRef`; an illegal
   `componentId` or param throws a Chinese error. The per-lib `ref.lib`
   checks inside the validators remain as a safety net.

3. **Browser bundle:** the editor inlines modules as flat strings
   (`embedded-editor.ts` + `VideoPackagingEditor.tsx#buildDocument`), which
   strips `import`/`export`. The three lint files share private names (`fail`,
   `validateLibraryRef`, `KNOWN_PARAMS`…), so flat concatenation would collide.
   Each lint source is therefore wrapped in an IIFE exposing only its plan
   validator (`bundleLint`), declared before the stripped `packaging-plan.js`.
   `embedded-editor.ts` gains `aikouLintJs` / `talkcraftLintJs` /
   `shotcraftLintJs` inlined constants, regenerated by
   `/tmp/regen-embedded.mjs` (round-trip verified: decode(encode(src)) ===
   src, and the pre-existing `packagingPlanJs` string decoded to the file
   before this change, proving the encoder matches the file's escaping).

## Alternatives considered

- **Renaming the colliding privates** (`aikouFail`, …): more churn across
  three files + specs; rejected in favor of the contained IIFE wrap.
- **Host-side shotcraft retrieval** (semantic search at plan time): the
  generated select-prompt already distills frontmatter + propsSchema per
  card, and prompt injection matches the aikou/talkcraft path; retrieval
  stays a future option if the 31-card prompt grows too long.

## Consequences

- `validatePackagingPlan` (and therefore `applyPackagingPlan`) now rejects
  illegal componentIds for all three open libraries in Node tests, the Host,
  and the browser editor alike.
- `embedded-editor.ts` is now four generated strings behind the sources;
  the durable fix remains a checked-in generator script (the regen one-liner
  used here lives in /tmp and is not committed).
- An existing plan spec (`video-packaging-plan.spec.ts`) used
  `componentId: 'x'` as a placeholder for "any integrated lib" — updated to
  real per-lib refs plus a new illegal-ID rejection test.

## Testing

  skip the gate, talkcraft/shotcraft prompts cover their whitelists.
